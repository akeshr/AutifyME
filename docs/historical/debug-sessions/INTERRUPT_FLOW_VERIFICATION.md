## Correct Architecture

### Phase 1: Interrupt Detection (Runner's Job)

```
Runner
  ↓ streams PM.stream(raw_message)
  ↓ for event in pm.stream():
  ↓     if "__interrupt__" in event:
  ↓         Extract interrupt_value
  ↓         Parse draft Product
  ↓         Send approval request to user
  ↓         Return (wait for user)
```

### Phase 2: Message Interpretation (PM's Job)

```
Runner
  ↓ receives new message from user
  ↓ forwards raw message to PM
PM
  ↓ calls MessageIntentSpecialist
  ↓ Specialist sees conversation history
  ↓ Detects: "Last message was approval request"
  ↓ Returns: {"intent": "approval_response", "decision": "approve"}
PM
  ↓ Returns this interpretation to Runner
```

### Phase 3: Resumption (Runner's Job)

```
Runner
  ↓ Receives PM's interpretation: approval_response
  ↓ Queries checkpoint for interrupt_id
  ↓ Builds Command(resume={interrupt_id: {"type": "accept"}})
  ↓ Streams PM with Command
  ↓ PM resumes → save_product executes
```

## Implementation Correction Needed

### Runner Responsibilities (Can't be delegated to PM!)

1. **Stream PM** and detect `"__interrupt__" in event`
2. **Send approval request** when interrupt detected
3. **On user response**, invoke PM to interpret intent
4. **If approval**, query checkpoint + build Command + resume PM

### PM Responsibilities (Via MessageIntentSpecialist)

1. **Interpret raw messages** in conversation context
2. **Return intent** to Runner (approval_response, new_cataloging, etc.)
3. **PM does NOT handle interrupts directly** - it can't, it's paused!

---

## Why This Division?

**Runner = External Observer**
- Streams PM execution
- Detects interrupts from outside
- Resumes with Command

**PM = Internal Orchestrator**
- Interprets messages using context
- Delegates to departments
- But CANNOT see its own interrupt state while paused

**Department = Workflow Executor**
- Executes domain logic
- Triggers interrupts via tool_configs
- Interrupt propagates up to PM's stream

## Key Takeaways

1. ✅ **Interrupts DO propagate** from department → PM's event stream
2. ✅ **Runner MUST detect** interrupts (external observer pattern)
3. ✅ **PM interprets messages** but doesn't handle its own interrupts
4. ✅ **Command resumption** happens in Runner, not PM
5. ✅ **MessageIntentSpecialist** still valuable for interpretation
6. ⚠️ **Our PM prompt was wrong** - PM can't check `state.get("__interrupt__")`
